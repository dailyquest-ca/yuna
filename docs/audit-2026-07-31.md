## Part 1 — Engineering review

### What holds up

- The heartbeat contract is genuinely good. Every failure this session was diagnosed from
  `runs.detail` in under a minute, and the `if: failure()` autopsy caught two deaths that
  happened before the heartbeat opened. Keep it exactly as is.
- Migrations are numbered, idempotent, and carry their reasoning in comments. `_migrations`
  tracking means the machine's schema history is auditable.
- Guard triggers actually enforce "the machine computes, Yuna judges" at the schema level.
- The point-in-time fundamentals capture is the best thing built this session — it converts a
  documented impossibility (§4.8) into a working compounder backtest.

### What does not — ranked

**Q1. No tests. None.** Zero test files for a system that sizes real money. Every formula in
`score.py`, `rank.py`, and both backtests is verified only by me eyeballing outputs. Four of the
seven bugs found this session (the exit rule, the NaN volume baseline, the C1 financial
exclusion, the `select *` view) would have been caught by a ten-line unit test. This is the
single largest quality gap and it is not close.

**Q2. `rank.py` and `funnel.py` are a different codebase.** They predate `db.py` and duplicate
`db_url()`, the heartbeat open/close, the retry loop, and the percentile function. `rank.py`
also uses a visibly different style — semicolons, no spaces around operators, 200-character
lines. Six of thirteen modules do not import `db.py`. A first-time reader meets two conventions
and has to learn both.

**Q3. Dependencies are declared nine different times, inline, in YAML.** There is no
`requirements.txt` or `pyproject.toml`. `numpy` and `pandas` are unpinned. A pandas release that
changes `rolling()` defaults would silently alter results — which is *exactly* the class of bug
that produced the 2%-vs-29% volume discrepancy.

**Q4. The backtest hardcodes what the live jobs read from config.** `backtest.py` line 194 sets
`budgets = {70: 0.007, 85: 0.009}`; `phase0.py` reads the same numbers from the `config` table.
Change the config and the simulation silently stops matching the machine.

**Q5. Two different blackout windows.** `daily.py` uses `blackout_days * 1.6 + 1` (≈9 calendar
days); `phase0.py` uses a hardcoded `current_date + 8`. Neither counts trading days, which is
what §3.3 specifies. Same rule, three interpretations.

**Q6. Dead and duplicated code.** `funnel.py` defines `ok_ex` and never uses it.
`backtest_compounders.py` imports `backtest` solely for `summarise()` — that belongs in a shared
module. `score.py` computes `pfcf_obs` and throws it away; there is no column for it.

**Q7. No local development path.** No `.env.example`, no way to run a job against a scratch
database. Every change costs a push, a dispatch, and a wait. That round-trip is why this session
took four iterations to get the backtest right.

**Q8. `backup.py` and `migrate.py` have no `DRY_RUN`** — §4.2 says all jobs carry it.

**Q9. Column overloading.** `backtest_trades.mcn` stores CCN on compounder runs. Anyone reading
that table without knowing which sleeve produced the row will misread it.

## Part 3 — Lessons

1. **Green is not a result.** Every serious defect this session shipped green: 9 trades in two
   years, a $4 microcap ranked #1, a 1.6× P/FCF on the buy list. The heartbeat proves a job
   *ran*, never that it was *right*. The habit that actually worked was cross-checking the
   model's own output against an independent query on the raw data — the SQL that said 29% of
   breakouts confirm on volume is what exposed a 2% simulation.

2. **Write the check before the feature.** Four of seven bugs were unit-testable in ten lines.
   I wrote none, because each individual piece looked obviously correct. They always do.

3. **A rule stored is not a rule enforced.** Twelve config keys and five schema columns encode
   plan rules that no line of code reads. Seeding a value *feels* like implementing it. It is
   the most common failure mode in this codebase and it is invisible without an audit like this.

4. **When the plan describes a mechanism, implement the mechanism, not the intent.** §5.1 says
   the volume condition is verified *after* the order fills. I implemented "refuse to enter",
   which is a different system and returned nine trades. Reading the sentence again fixed it.

5. **Silence is the enemy.** The batch insert that fell back to row-by-row printed to stdout and
   went green, dropping an entire column. Anything that degrades must reach the heartbeat.

6. **Say the deviation out loud, at the time.** The announced deviations (3-year median,
   compounder P/FCF) caused no trouble. The unannounced ones (theme = sector, the base-detection
   algorithm) are the ones that turned out to matter most.

7. **Check the vendor's claims against the vendor's own data.** `CurrencyCode` said USD for a
   company filing in TWD, and EODHD's own `PriceSalesTTM` made the same mistake. The statement
   rows knew the truth.
